## 1. 설계 원칙

1. **판정은 한 곳에서만 정의한다.** 두 로더가 같은 술어를 공유한다. 복제하면 `test-core-logic.html` 이 지고 있는 동기화 부채가 하나 더 는다.
2. **기존 회귀 검증을 깨지 않는다.** `page_grade_digest` 는 `(교재, 페이지, 등급)` 만 해싱하므로(`recount_grades.py:219-223`) 열·키 추가는 digest 를 바꾸지 않는다. 이것을 시험으로 고정한다(R12j).
3. **실 데이터 없이 검증 가능해야 한다.** `data/` 는 gitignore 이므로 모든 신규 어서션은 스텁 워크북 위에서 돈다.

## 3. 신규: 절단 판정 술어

**위치**: `page_utils.py` (리포의 유일한 공유 lib). 두 스크립트 모두 저장소 루트에 있어
`import page_utils` 가 경로 조작 없이 동작한다. 술어 하나 때문에 세 번째 모듈을 만드는 것보다 낫다.
`CLAUDE.md` 의 `page_utils` 설명에 이 함수를 추가한다.

```python
EXCEL_MAX_CHARS = 32767          # add_fullpage.py:22 와 같은 값
TRUNCATION_MARK = '...'


def is_cell_truncated(text):
    """엑셀 셀 한도에 붙어 잘린 본문인지 판정한다.

    add_fullpage.py:83 은 `full_content[:EXCEL_MAX_CHARS - 3] + '...'` 로 자르므로
    잘린 셀은 정확히 32,767자이고 '...' 로 끝난다. 두 조건을 **모두** 요구한다.

      길이만 보면  원래 정확히 32,767자였던 본문을 절단으로 오판한다.
                   그런 본문은 `len > MAX` 가 거짓이라 자르지 않고 통과하므로
                   '...' 가 붙지 않는다 — 마커가 이 둘을 가른다.
      마커만 보면  '...' 로 끝나는 짧은 본문을 전부 절단으로 오판한다.

    남는 오탐은 "원래 정확히 32,767자이면서 '...' 로 끝나는 본문" 하나뿐이다.
    실측 NCS 1,847쪽·교과서 362쪽에서 두 조건이 갈리는 사례는 0건이었다.
    """
    return (isinstance(text, str)
            and len(text) == EXCEL_MAX_CHARS
            and text.endswith(TRUNCATION_MARK))
```

## 4. FR-1 — 절단 탐지와 플래그 전파

### 4.1 `recount_grades.py` — 열 매핑 없이 판정한다

§0-1·§0-2 때문에 "본문 열을 찾아서 읽는" 접근은 쓰지 않는다. 절단 마커가 **자기 식별적**이므로
행의 모든 셀을 훑어 하나라도 절단이면 그 행의 본문이 잘린 것이다. 교과서의 다른 열 배치에도
그대로 동작한다.

```python
# parse_row() 안, return 직전
return dict(case=x, raw=int(v[i + 1]), ...,
            truncated=any(is_cell_truncated(y) for y in vals))
```

> **`v` 가 아니라 `vals` 를 본다.** `v` 는 `str(x).strip()` 을 거친 값이라, 셀 앞에 공백이
> 있으면 길이가 32,767 미만으로 줄어 탐지에 실패한다. 원시 값에서 판정한다.

`page_record()` 는 **OR 로 접는다** — 한 행이라도 잘린 본문을 실었으면 그 페이지의 본문은 잘렸다.
등급의 `min` 규칙과 달리 여기서는 보수적 방향이 OR 이다.

```python
return dict(rep, g=grade, case=case,
            truncated=any(x['truncated'] for x in page_rows))
```

`aggregate()` 에 두 키를 더한다. digest 계산식은 손대지 않는다.

```python
'truncated_pages': sum(1 for x in by_page.values() if x['truncated']),
'truncated_page_g': {g: sum(1 for x in by_page.values()
                            if x['truncated'] and x['g'] == g) for g in (1, 2, 3)},
```

`EXPECTED` 에 실측값을 추가한다. 회귀 검증이 이 값을 지킨다.

```python
'ncs': {..., 'truncated_pages': 16, 'truncated_page_g': {1: 0, 2: 4, 3: 12}},
'txt': {..., 'truncated_pages': 0,  'truncated_page_g': {1: 0, 2: 0, 3: 0}},
```

## 5. FR-2 — 코딩 시트의 6,000자 절단 제거

`make_coding_sheet.py:65,91-97` 을 바꾼다.

- **`MAX_CHARS = 6000` 삭제.** 본문을 자르지 않는다. 채점기와 코더가 같은 텍스트를 본다.
- **`truncated` 필드 의미 충돌 해소.** 현재 이 이름은 "6,000자에서 잘랐다"는 뜻이다. 더 이상
  자르지 않으므로 제거하고, 원본 절단을 뜻하는 `cell_truncated` 를 새로 넣는다. 같은 이름을
  다른 뜻으로 재사용하면 과거 산출물과 조용히 어긋난다.
- **긴 항목은 분할 제시.** 6,000자를 넘으면 문단 경계에서 끊어 `(본문 1/6)` … `(본문 6/6)`
  펜스 블록으로 나눈다. 항목 번호와 `판정: ____` 줄은 하나만 유지한다 — 항목이 쪼개져 보이면
  코더가 같은 페이지를 여러 번 판정하게 된다.
- **절단 항목에는 고지를 붙인다.**

  ```
  > ⚠️ 이 본문은 원본 수집 단계에서 잘렸습니다(엑셀 셀 한도 32,767자).
  > 뒷부분은 **존재하지 않습니다.** 뒤에 조치가 더 있었는지는 알 수 없으므로,
  > 판단이 서지 않으면 `?` 로 표시하십시오.
  ```

  **앵커링 검토.** 이 고지가 규칙의 판정을 누출하는가 — 아니다. 절단은 데이터 품질 사실이고
  등급과 무관하게 기술된다. 그리고 전문을 보여주는 순간 말미의 `...` 로 절단은 이미 드러난다.
  고지는 이미 노출된 것을 명시할 뿐이다. **고지하지 않는 쪽이 위험하다** — 코더가 잘린 뒷부분의
  부재를 "조치 없음"으로 읽는 것이 C-1 이 지적한 오염 그 자체다.

  다만 절단쪽이 분쟁군에 몰려 있으므로(§0-3, 등급3의 11.1%) 코더가 "절단 = 특정 군" 을 학습할
  여지는 남는다. 이것은 고지를 빼서 막을 수 없고 **층화 분석(FR-3)으로 흡수한다.**

- `coding_key.json` 레코드에도 `cell_truncated` 를 넣는다. 채점 단계에서 층을 알아야 한다.

## 6. FR-3 — 층화 보고

`score_coding.py` 의 출력에 절단층/비절단층을 분리한다. 통합 수치만 내면 §0-3 의 집중도가
가려진다 — 통합 κ 가 층 구성의 산물이었다는 `TODOS.md:36` 의 지적과 같은 실수다.

- 층별 등급 분포와 코더 간 일치도를 각각 낸다.
- 층 크기가 작으면(절단층 9항목) 수치 대신 **원자료를 나열**한다. 9개에서 κ 를 뽑아 소수점
  셋째 자리까지 적으면 없는 정밀도를 주장하게 된다.
- **민감도는 F1 이 아니라 분쟁군 지지율로 낸다.**

> ⚠️ **정정 (Act-1, 2026-09-04).** 이 절은 원래 "규칙 대비 F1 을 층별로 낸다" 였다.
> 두 가지가 틀렸다. ① 분쟁군은 **전수** 표집이라 절단 항목을 빼면 표본 수치를 모집단
> 예측 수로 나누는 §4·§5 계산의 가중이 어긋난다 — 통계가 무너진다. ② 9항목에서 나온 F1
> 은 신뢰구간이 변형 간 차이(0.02~0.04)보다 넓어 판별력이 없다(감사 M-3 과 같은 이유).
> 대신 **분쟁군의 '수정본 지지율'을 절단 포함/제외로 병기**한다. 비율이라 표본이 줄어도
> 해석이 유지되고, 두 값이 벌어지면 "수정본 우세가 절단 인공물" 이라는 가설이 바로 보인다.
> 배치도 `score_variants()` 가 아니라 `strata()` 가 맞다 — 규칙 변형 재실행이 필요 없다.

## 9. 검증 불가 항목 [→E2E]

- **실 워크북 실측치(16쪽 / 1,376행 / 교과서 0)는 CI 에서 돌지 않는다.** `data/` 가 gitignore 다.
  스텁으로 로직을 고정하고, 실측치는 `EXPECTED` 와 문서에 기록해 `recount_grades.py` 를 실제로
  돌릴 때 회귀 검증이 잡도록 한다.
- 코딩 시트의 가독성(32,767자 항목을 코더가 실제로 끝까지 읽는가)은 자동화 대상이 아니다.
