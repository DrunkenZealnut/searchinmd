## 5. 결론

기능의 실체 — 하이브리드 배정 알고리즘, 회귀 가드 갱신, 대시보드 3종의 수치 교체, 하니스 정본 이관 — 은 설계대로 전부 들어갔고, 독립 재계산 24개 항목이 **한 건도 어긋나지 않았다**. 파생 수치까지(영역 비율, %p 차이, 0쪽 교재의 영역별 분해, 쪽당 검출 건수) 손으로 다시 계산해 확인했다. `hybrid_pages` 는 설계 §1 의 문장을 그대로 코드로 옮긴 수준이고, R16z15 가 다섯 규칙을 개별 픽스처로 고정한다.

남은 것은 전부 **한 종류의 결함**이다. 수치는 바꾸면서 "아직 안 바꿨다" 는 옛 문장을 지우지 않아, 네 문서가 자기 자신과 모순한다(H-1·H-2·H-3·M-1). 그중 둘은 README 와 결과 문서의 **가장 먼저 읽히는 자리**에 있어, 이 상태로 공개되면 독자가 대시보드의 2,189쪽을 라벨 기준 1,847쪽으로 오인할 수 있다. 착수 순서는 H-1 → H-2 → H-3 → M-1 → M-2 이고, 다섯 건 모두 한 문장 삭제나 숫자 치환이다.

구조적으로 하나 남는 것은 L-4 다. `hybrid_lines` 2,741 은 결과 문서가 인용하는데 `EXPECTED` 가 잡지 않는 유일한 수치로, 이 저장소가 다른 모든 발표 수치에 적용해 온 규칙에서 벗어나 있다. L-5 는 같은 성격의 커버리지 구멍이다 — 지금은 맞지만 다음 변경 때 조용히 틀어질 자리다.
