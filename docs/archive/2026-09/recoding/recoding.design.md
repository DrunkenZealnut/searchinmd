## 1. 설계 원칙

1. **코더는 규칙을 절대 보지 않는다.** 코딩 프로세스가 `regrade.py`·`recount_grades.py`·
   등급 카운트·사유 문자열에 접근할 경로 자체를 만들지 않는다. 지난 회차의 1번 오염원이다.
2. **한 항목 = 한 호출.** 컨텍스트를 공유하면 항목 간 상대평가가 생긴다(지난 회차 4번).
3. **제공자는 갈아끼울 수 있어야 한다.** 코더 구성이 바뀔 때 코드가 아니라 설정이 바뀌어야
   한다. 계열 다양성이 이 작업의 핵심 요건이라 여기가 굳으면 안 된다.
4. **모든 판정은 원자료를 남긴다.** 응답 원문·토큰 수·지연·재시도 횟수까지. 나중에
   "왜 이 라벨이 이렇게 나왔나" 를 물을 수 있어야 한다.

## 2. 코더 아키텍처

### 2.1 신규 `code_pages.py` — 얇은 항목별 호출기 (구현됨)

```
code_pages.py --coder B --provider-env ~/.config/auditagent/.env [--model gpt-5.6-sol]
code_pages.py --coder A --provider-env .env.local --model <제3 제공자 모델> --resume
              [--sheet coding_sheet.json] [--out coding_<코더>.json] [--base-url URL]
              [--temperature 0] [--seed 20260904] [--limit N] [--dry-run]
```

- **OpenAI 호환 `/chat/completions` 만 쓴다.** `AUDIT_LLM_BASE_URL`·`AUDIT_LLM_API_KEY`·
  `AUDIT_LLM_MODEL` 을 우선 읽고, 없으면 **키 변수명 프리셋**(`OPENAI_API_KEY`, `GEMINI_API_KEY`
  / `GOOGLE_API_KEY`, `DEEPSEEK_API_KEY`, `GROQ_API_KEY`, `OPENROUTER_API_KEY`)으로 주소를 고른다.
  제공자를 바꾸는 것은 env 파일을 바꾸는 일이지 코드를 바꾸는 일이 아니다. 모델은 기본값으로
  때우지 않는다 — 없으면 거부한다(R15j6).
- **온도는 인자 기본값 0.** `.env` 의 `AUDIT_LLM_TEMPERATURE` 를 **상속하지 않는다**(제약 3,
  R15j5 — 소스에 그 변수명 자체가 없다).
- **온도·시드를 거부하는 모델**(400)이면 그 인자만 빼고 즉시 다시 묻고 `meta.temperature_honored`
  / `seed_honored` 에 False 를 **기록**한다. 같은 파일의 뒤 항목은 처음부터 빼고 보낸다(R15l7).
- **재개 가능.** 항목마다 산출물을 원자적으로 갱신하고(`tmp` + `os.replace`, R15l2) `--resume` 이
  채점된 항목을 건너뛰되 오류 항목은 다시 묻는다(R15l5). 진행 상태는 산출물 자체다 — 별도
  progress 파일을 두지 않는다. 다른 모델·주소로는 재개할 수 없고(R15l6), 있는 산출물을
  `--resume` 없이 덮어쓰지 않는다.
- **프롬프트는 시트에서 온다.** `coding_sheet.json` 의 `coder_prompt` 가 system, 항목 본문(절단
  항목은 `notice` + 본문)이 user 다. 스크립트는 규칙 지식을 문자열로 갖지 않는다 — R15m 이
  소스에서 등급 정의·동음이의 문자열 부재를 검사한다(원칙 1).
- **라벨은 확실할 때만.** 응답에서 1·2·3·`?` 가 홀로 선 값이 **정확히 하나**일 때만 라벨을
  만들고, 둘 이상이거나 없으면 `errors` 에 남긴다(R15k, R15l). 429·5xx·네트워크 오류는
  1·2·4·8·16초 물러서며 5회까지 재시도하고 횟수를 기록한다(R15l8).

산출물:

```json
{ "coder": "A", "sample_digest": "<coding_key 와 동일>",
  "meta": { "model", "model_reported", "version": "<system_fingerprint>", "base_url", "key_var",
            "temperature": 0, "temperature_honored", "seed": 20260904, "seed_honored",
            "prompt_sha256", "run_at", "context_isolated": true, "provider_env", "resumed_at": [] },
  "grades": { "1": 3, "2": "?", ... },
  "errors": { "5": "응답을 1·2·3·? 로 읽을 수 없음: ..." },
  "raw": { "1": {"answer", "tokens_in", "tokens_out", "latency_ms", "retries"}, ... } }
```

`grades` 는 `score_coding.py` 가 읽는 기존 형식 그대로다. `meta` 가 FR-3, `raw` 가 원칙 4.
제공자가 `system_fingerprint` 를 주지 않으면 `version` 은 null 이고 `model_reported`(응답의 `model`)가
대체 기록이다 — 2026-09-04 두 실행 모두 그랬다.

**`--backend claude-cli` (A1 경로, 키 불필요)**: 항목마다 `claude -p` 를 한 번 띄운다(로그인된 Claude Code 의
OAuth). 어댑터 `claude_cli_post()` 가 post 인터페이스를 구현해 나머지 경로(재개·파싱·기록)를 그대로 탄다.
강제 옵션: `--setting-sources ""`(설정·훅·플러그인·CLAUDE.md 차단) · `--tools ""` · `--strict-mcp-config`
(MCP 도구 정의 차단 — 제약 9) · `--no-chrome` · `--no-session-persistence` · 저장소 밖 cwd. 온도·시드는
CLI 가 받지 않으므로 어댑터가 400 을 돌려 `*_honored=False` 로 기록된다. Claude Code 가 끼워 넣는 Haiku
보조 호출(항목 본문도 본다)은 `raw[id].side_calls` 에 남기고 코더로 세지 않는다. `--workers N` 은 호출만
병렬이고 기록은 항목 순서다(R15s–s5).

### 2.2 코더 A 를 무엇으로 할 것인가 — 열린 선택

B 는 `gpt-5.6-sol` 로 확정됐다. A 는 아직 정해지지 않았고, 제약 1 때문에 갈래가 셋이다.

| 안 | 방식 | 계열 다양성 | 비용·부하 | 추가 필요 |
|---|---|---|---|---|
| **A1** | Claude Code 서브에이전트 514회 | Claude vs OpenAI (2계열) | **높음.** 항목당 에이전트 1개, 서브에이전트 오버헤드 포함 | 없음 |
| **A2 (권장)** | 제3 제공자를 `code_pages.py` 로 (Gemini / DeepSeek) | **3계열까지** 가능 | 낮음. B 와 같은 경로 | 해당 제공자 API 키 |
| **A3** | Ollama 로컬 | Claude·OpenAI 외 (2계열) | 무료, 느림 | 로컬 모델 설치. 한국어 안전문 분류 품질 미검증 |

**A2 를 권한다.** 코더 둘이 같은 코드 경로를 타면 프롬프트·온도·재시도가 구조적으로
동일해져 "코더 차이" 가 모델 차이만 남는다. A1 은 한쪽만 에이전트 프레임을 쓰게 되어
비교가 지저분해지고, 부하도 가장 크다.

**이 선택은 설계를 바꾸지 않는다** — `code_pages.py` 는 셋 다 지원한다(A1 만 별도 경로).
정하지 않아도 Do 단계의 다른 부분은 진행할 수 있다.

**결정: A2** (2026-09-04, 연구 책임자). 키는 `.env.local` 에 두기로 했다. 다만 그 파일에는
현재 `OPENAI_API_KEY` 만 있어(제약 7) 이대로는 B 와 같은 계열이다. Gemini/DeepSeek 키와 모델명이
들어오면 `python3 code_pages.py --coder A --provider-env .env.local --model <모델>` 로 돌린다.
코더 B 는 `~/.config/auditagent/.env` 로 지금 돌릴 수 있다(dry-run 확인, 2026-09-04).

**FR-1 회차 (2026-09-04, 연구 책임자 지시 "anthropic 모델로 한번 더")**: 코더 **C = `claude-opus-5`** 를
`--backend claude-cli` 로 돌린다(API 키 없음 → A1). 대조는 `score_coding.py --coders C,B` (Claude vs OpenAI).
A(OpenAI 재시행)는 기록으로 남기고 `--coders C,A` 는 참고용이다. **결과 (2026-09-04)**: 538/538, C·B κ 0.685
(같은 모델 A·B 는 0.914), FR-1 경고 없음. 첫 스모크 2항목은 MCP 도구 정의가 실린 채 나와 폐기하고 다시 돌렸다.

**실행 기록 (2026-09-04)**: 연구 책임자가 OpenAI 키만으로 진행하기로 해 A 도 `gpt-5.6-sol` 로 돌렸다
(`.env.local` 의 `OPENAI_API_KEY`). FR-1(계열 상이)은 **미충족**이고 채점기가 경고를 찍는다(§4.4). 다음
회차에 다른 제공자 키로 A 만 다시 돌리면 같은 표본·지문이 유지된다(§6-8).

## 3. 표본 생성 — `make_coding_sheet.py` 4층, 두 어휘 정의의 **합집합** (구현됨)

어휘 21종(§5)의 채택 여부를 라벨 없이 먼저 정하면 순환이다(Plan §8: "어느 변형을 채택할지는
이 데이터가 정한다"). 그래서 현재 사전과 확장 사전(V) **두 정의의 합집합**으로 층을 뽑아, 같은
라벨로 아홉 변형 전부를 채점한다. 비용은 514 → 538쪽(+24)이고, 대가로 어휘 채택도 라벨이
판정한다. 근거: D1+D2 계열 변형의 등급3은 같은 어휘의 현행 등급3에 포함되므로(실측 72=합의군
72, 90=합의군 90) 합집합의 전수 대상은 "현행+V 등급3" 129쪽 안에 닫힌다 — 다만 코드는 이
단조성에 기대지 않고 **어느 변형이든 3이면** 전수에 넣는다(R15f 의 p9).

| `group` | 정의 (규칙쌍 = (현행, D1+D2) × 어휘 {현재, V}) | 쪽수 | 글자 수 | 답하는 질문 |
|---|---|---:|---:|---|
| `disputed` | 어느 쌍에서든 현행=3 & 수정본≠3, **전수** | **44** (36 ∪ 39) | 435,425 | 수정본이 옳은가 — 쌍별 지지율 (§4.1) |
| `control` | 어느 변형이든 3인 쪽 − 분쟁군, **전수** | **85** | 222,634 | 코더가 등급3에 인색한가 (기준선) |
| `boundary` | 등급3 아닌 쪽 중 어느 쌍에서든 현행=2 & 수정본=1, **전수** | **109** (106 ∪ 100) | 440,612 | 가장 많이 움직인 경계 (FR-6). 여기서 3 은 두 규칙 공통의 누락 |
| `recall` | 나머지 1,609쪽에서 무작위 300 | **300** | 376,341 | 재현율 (FR-7) |
| 합계 | | **538** | 1,475,012 | 코더 2명 = 1,076회 |

(2026-09-04 실측, `python3.13 make_coding_sheet.py`. 절단 16항목 전부 포함, 분할 제시 34항목,
표본 지문 `68a4575ffff0def9`.)

```python
N_RECALL = 300
SEED = 20260904          # 표본이 바뀌었으므로 시드도 새로 둔다. 옛 시드(20260903)는 옛 표본의 것
RULE_PAIRS = [('baseline', RG.ADOPTED_VARIANT), (RG.VOCAB_VARIANT, RG.ADOPTED_VOCAB_VARIANT)]
```

- 변형 라벨은 `regrade.variant_grid()` 가 소유한다. `make_coding_sheet` 와 `score_coding` 의 새
  경로는 라벨을 다시 타이핑하지 않는다(R15d). 구경로 `score_variants()` 의 표시용 라벨은 그대로다.
- `strata(preds)` 는 순수 함수라 합성 예측으로 시험한다(R15e–g). `draw()` 가 재현율층만
  무작위로 뽑고 섞는다(R15h). `N_CONTROL` 은 없앴다 — 합의군은 전수다(R15h2).
- **키가 변형별 예측을 싣는다**: 항목마다 `pred: {변형: 등급}` (baseline + 8변형), 문서 머리에
  `population {pages, recall_pool, strata}`·`variants`·`rule_pairs`·`seed`. 채점기가 원본 엑셀
  없이 정밀도를 내고, 전수라 **표본→모집단 가중치가 사라진다**(Plan §4.1).
- **시트가 지시문을 싣는다**: `coder_prompt`(등급 정의 + 응답 형식 "1·2·3·? 중 하나만"), 절단
  항목엔 `notice`. 사람용 `.md` 와 API 코더가 **같은 문자열**을 본다. 시트 항목에는 등급·카운트·
  군이 없다(R15i, R15i2, R15i3 — 누출 문구 부재도 같이 검사).
- `sample_digest` 는 `(교재, 쪽, 군)` 해시라 층이 늘어도 그대로 동작한다.
- 옛 라벨 삼종(κ 0.796 의 기록)은 `docs/archive/2026-09/coding-v1/` 로 옮겼다 — 추적은 유지하고
  루트의 이름은 새 산출물이 쓴다.

## 4. 채점 — `score_coding.py` 전수 + 재현율층 (구현됨)

### 4.1 두 경로

키가 새 형식(`population` + 항목별 `pred`)이면 `main_census()`, 구형식이면 `main_legacy()`(기존
코드 그대로, R13ae·R14n 이 계속 지킨다). 새 경로의 절: 1 전체 일치도 → 2 층별 분포·일치도 →
3 분쟁군 **규칙쌍별** 지지율(현재 어휘 쌍 / V 쌍 따로) → 3-1 절단층(기존 `strata()`) →
4 재현율층 → 5 변형별 정밀도·재현율·F1.

가드 둘: 재현율층에 등급3 예측이 있으면 멈춘다(R15o7). `check_population()` 이 키의 변형별
등급3 전수를 `regrade_impact.json` 분포와 대조해 하나라도 어긋나면 멈춘다(R15o8) — 규칙이
바뀌었는데 표본이 옛것인 상태를 잡는다. 두 가드가 "어느 변형의 등급3이든 표본에 다 있다" 를
실행 시점에 보증하므로 정밀도는 **표본 가중 없이** 그대로다(R15o).

수치는 보고서 문장으로만 남기지 않고 `docs/03-analysis/data/recoding_scores.json` 에도 쓴다
(표본 지문, 두 코더의 meta, 층별 일치도, 변형별 정밀도·재현율·구간, 계열 경고; NaN 은 None).
분석 문서 `recoding-results.analysis.md` 의 숫자는 전부 이 파일에서 온다(R15o10·o11, R15p2) — 불일치
패턴, 규칙쌍별 지지율, 절단층 통계, "둘 다 3" 재현율 추정까지 `res` 에 싣는다.

### 4.2 재현율 — 처음 측정

현행이 등급1·2로 둔 1,739쪽 중 경계층 109쪽은 전수, 나머지 1,609쪽(N)에서 300 을 뽑았다.

```
진짜 등급3 총계 T = C + K̂        C = 전수 3층에서 코더가 3 이라 한 수 (표집오차 0)
                                  K̂ = h·N/n  (재현율층 적중 h, 유효 n)
변형 R 의 재현율   = TP_R / T,   구간 = [TP_R/(C+K_hi), TP_R/(C+K_lo)]
```

K 의 구간은 **정확 초기하**(Clopper-Pearson 형, `missed_interval`)다. 초안의 Wilson+FPC 를
바꾼 이유: n=300 에 h 가 한 자릿수면 정규 근사가 하한을 음수로 만든다. **h=0 → 점추정 없이
단측 95% 상한만**: N=1,739·n=300 이면 15쪽(R15n). 전수(n=N)면 구간이 점으로 닫힌다(R15n3).
`?` 는 재현율층에서도 유효 n 에서 빠진다(R15o3).

### 4.3 신뢰구간 병기 (감사 M-3)

정밀도는 전수라 표집오차가 없고, **코더 신뢰도** 오차를 "[양쪽 모두 3, 한쪽이라도 3]" 폭으로
병기한다(R15o5). 재현율은 §4.2 의 구간. Plan §8 의 성공 기준("그 구간이 변형 간 차이보다
좁은지")은 이 두 폭으로 판정한다.

### 4.4 층별 보고 + 계열 가드

`strata()` 의 절단 축은 그대로, 군 축은 2절이 낸다. `family_guard()` 가 두 코더의
`meta.base_url` 호스트가 같으면 **FR-1 미충족** 경고를 낸다(R15o9) — 제약 7 의 상태로 돌리면
보고서 끝에 경고가 찍힌다.

## 5. 어휘 탐색 — 표본보다 먼저 (Plan §5)

**표본을 뽑기 전에** 해야 한다. 어휘가 바뀌면 `disputed`/`boundary` 정의가 바뀌고 표본이
통째로 달라진다.

`regrade.py` 는 이미 `--validate` 로 규칙만 재실행할 수 있으므로, 어휘 후보를 넣고
분포 변화를 보는 것은 코드 변경 없이 가능하다.

**순환 방지 규약** (응답서 §7-c): 어휘 후보는 **본문에서** 찾고 라벨은 쓰지 않는다.
라벨을 결함 발견에 쓰는 것과 변형 선택에 쓰는 것은 다르다 — 후자만 순환이다.

산출물은 `docs/03-analysis/vocab-search.analysis.md`: 후보 어휘, 각각의 등급 분포 영향,
채택/기각과 사유.
