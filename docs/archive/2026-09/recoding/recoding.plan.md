## 1. 왜 기존 라벨을 못 쓰는가

네 가지가 겹쳐 있고, 각각 독립적으로 라벨을 무효로 만든다.

| # | 오염 | 근거 |
|:--:|---|---|
| 1 | **코더 A가 규칙 작성 당사자** | 응답서 §1 자진 신고. `SAFETY_TERMS`·임계값·`HOMONYM_CONTEXTS`·정규화 형태를 전부 설계한 뒤 코딩했다. 규칙에 맹검이 아니었다 |
| 2 | **지시문이 규칙을 누출** | 코딩 시트가 D1의 동음이의 가정(`진동`·`먼지(파티클)`)과 "판단이 갈리면 낮은 등급" 이라는 **방향성** 동점 규칙을 두 코더 모두에게 줬다. 후자는 수정본이 이기는 방향이다. `e37cbce` 에서 제거됨 |
| 3 | **표본틀이 오염된 카운터로 뽑혔다** | 분쟁군 정의가 C-2 버그를 가진 `count_terms` 로 산출됐다. 수정 후 39 → **36쪽** |
| 4 | **두 코더가 같은 계열, 한 컨텍스트** | 둘 다 Claude. 69항목을 한 컨텍스트에서 순차 열람해 항목 간 상대평가가 발생했다(코더 B의 자체 노트가 이를 드러낸다) |

②와 ③은 코드에서 고쳤다. ①과 ④는 **이 계획이 처리할 일**이다.

## 4. 표본 설계 — 대부분 계산으로 정해진다

초안은 여기에 여섯 개의 열린 질문을 뒀는데, 계산해보니 과했다. **등급3 전체가
108쪽뿐이라 전수 코딩이 가능하다.** 전수면 표집오차가 0이므로 "표본 크기" 라는
질문 자체가 없어진다. "69쪽으로는 판별력이 없었다" 는 맞지만, 해법은 더 뽑는 것이
아니라 다 하는 것이었다.

### 4.1 전수로 가는 층 (표집오차 0)

| 층 | 쪽수 | 답하는 질문 |
|---|---:|---|
| 분쟁군 (현행 3, D1+D2 ≠3) | 36 | 수정본이 옳은가 |
| 합의군 (둘 다 3) | 72 | 코더가 원래 등급3에 인색한가 (기준선) |
| **소계 = 등급3 전체** | **108** | **정밀도. 전수라 신뢰구간 불필요** |
| 등급2 → 1 이동 | 106 | 재채점이 가장 많이 움직인 경계 |
| **합계** | **214** | 코더 2명이면 428회 판정 |

### 4.2 표본이 필요한 유일한 층 — 재현율

현행 등급1·2 **1,739쪽**. 여기 묻힌 진짜 등급3을 아무도 본 적이 없다.

| 재현율 표본 n | 총 코딩 | 적중 0건일 때 말할 수 있는 것 (95%, 유한모집단 보정) |
|---:|---:|---|
| 0 | 214쪽 | 없음. 재현율 미측정이 그대로 유지된다 |
| 150 | 364쪽 | 누락률 < 1.8% (약 32쪽 이하) |
| 300 | 514쪽 | 누락률 < 0.8% (약 14쪽 이하) |

참값이 2%라면 n=150 에서 기대 적중 3건, n=300 에서 6건이다. 적중이 나오면 추정치가
생기고, 0건이어도 상한은 진술할 수 있다.

### 4.3 결정 — 확정됨 (2026-09-04, 연구 책임자)

| 결정 | 답 | 귀결 |
|---|---|---|
| **A. 재현율 층 n** | **300 (최대)** | 총 514쪽. 적중 0건이어도 "누락률 < 0.8% (약 14쪽 이하)" 를 말할 수 있다 |
| **B. 코더 구성** | **다른 계열 모델 개입** — OpenAI `gpt-5.6-sol` (`auditagent` 경로) | 같은 계열 둘 문제 해소. 사람 코더는 이번 회차에 포함하지 않는다 |
| **C. 상업 교재 본문의 외부 API 통과** | **허용** | 로컬 모델 제약 없음. 권리관계는 연구 책임자 판단으로 종결 |

절단 9쪽은 **층화 병기**(FR-5).

### 4.4 확정 표본 (514쪽 / 1,483,087자)

| 층 | 쪽수 | 총 글자 | 평균 | 최장 |
|---|---:|---:|---:|---:|
| 분쟁군 (전수) | 36 | 422,474 | **11,735** | 32,767 |
| 합의군 (전수) | 72 | 209,907 | 2,915 | 32,767 |
| 등급2 → 1 (전수) | 106 | 434,633 | 4,100 | 32,767 |
| 재현율 표본 (1,739쪽에서 무작위) | 300 | 416,073 | 1,386 | 32,767 |
| **합계** | **514** | **1,483,087** | | |

**분쟁군 평균이 11,735자다** — 전체 페이지 길이 중앙값 1,066자의 11배. D2 정규화가
긴 페이지를 깎는다는 것의 직접 증거이고, 절단 9쪽이 왜 이 층에 몰렸는지도 같은 이유다.
코딩 부하가 층마다 크게 다르므로 일정 산정 시 쪽수가 아니라 글자 수로 봐야 한다.

항목별 독립 호출(FR-2) 기준 **514쪽 × 2코더 = 1,028회**.

### 4.5 B 확인 결과 — 설계가 처리해야 할 것 셋

`auditagent --check` 로 확인: OpenAI `gpt-5.6-sol`, 설정은 `~/.config/auditagent/.env`.
쓸 수 있지만 그대로는 안 되고 세 가지를 설계에서 풀어야 한다.

1. **`auditagent` 는 문서 감사 도구지 항목별 코더가 아니다.** 파일을 받아 보고서를
   내는 인터페이스(`auditagent <파일...> --type design`)라, 514항목을 하나씩 독립
   호출하는 용도로는 맞지 않는다. 같은 OpenAI 호환 엔드포인트를 직접 치는 얇은
   호출기가 필요하다. **설정은 재사용한다** — 키·모델·base URL 을 한 곳에서 읽어야
   두 벌이 어긋나지 않는다.
2. **`AUDIT_LLM_TEMPERATURE=1.0` 이다.** 코딩은 온도 0이어야 재현 가능하고, FR-3 이
   온도 기록을 요구한다. 코더 호출은 이 값을 상속하지 말고 명시해야 한다.
3. **`gpt-5.6-sol` 은 이 규칙의 외부감사를 수행한 그 모델이다.** API 는 무상태라
   호출 간 오염은 없지만, 감사 보고서에는 D1 의 동음이의 가정과 규칙 내부가 들어
   있다. 코더 프롬프트가 깨끗하면 문제되지 않으나 **기록은 해야 한다** — 코더 A 의
   독립성 실패를 자진 신고한 저장소가 이걸 빠뜨리면 같은 실수다.

| ~~상업 교재 본문이 또 API를 통과~~ | **결정됨** — 허용 (§4.3-C). 연구 책임자 판단으로 종결 |
| **감사 수행 모델이 코더로 들어온다** | `gpt-5.6-sol` 은 이 규칙의 외부감사를 한 모델이다. API 무상태라 호출 간 오염은 없지만 §4.5-3 대로 **공개문에 기록**한다 |
| 코더 온도가 1.0 으로 상속됨 | `auditagent` 기본값이 1.0 이다. 코더 호출은 0 으로 명시하고 FR-3 으로 기록 |

## 8. 성공 기준

이 작업이 끝났을 때 다음을 말할 수 있어야 한다.

- 각 규칙 변형(현행 / D1+D2 / D4 세 방식)의 정밀도·재현율·F1과 **신뢰구간**
- 그 신뢰구간이 변형 간 차이보다 **좁은지** — 좁지 않으면 "판별 불가" 가 정직한 결론이다
- 절단층을 넣고 뺐을 때 결론이 바뀌는지
- 등급2↔1 경계에서 수정본이 옳은지
- 재현율 추정치, 또는 최소한 그 상한 — n=300 이라 적중 0건이어도 **누락률 < 0.8%(약 14쪽)** 는 말할 수 있다

말할 수 없어야 하는 것: **어느 변형을 채택할지는 이 데이터가 정한다.** 계획서가 미리 정하지 않는다.
