## 6. 한계와 남은 것

### 6.1 온도 미보장

두 모델 모두 `temperature` 인자를 거부해 온도 없이 호출됐다. 메타에 `temperature_honored=false` 기록. **재현 보장 안 함.**

### 6.2 Claude는 claude -p 경유 + Haiku 보조 호출

API 키가 없어 `claude -p` 헤드리스로 실행. Claude Code가 끼워 넣는 Haiku 보조 호출이 항목 본문을 본다 — 코더로 세지 않고 `raw[id].side_calls`에 기록. 495항목에서 발생.

### 6.3 사람 코딩 없음

세 모델 모두 LLM. 사람 판정 수치 없음 — §5.3의 하한/상한은 계열 간 일치/불일치일 뿐 진짜 답이 아니다. 판별점: 두 계열이 모두 등급3이라 한 누락 79쪽(재현율층 51 + 경계층 28).

### 6.4 어느 변형도 채택하지 않음

이 보고서는 **결함 발견**이지 변형 선택이 아니다. 발표 수치 변경은 연구 책임자 판단.

### 6.5 발표 수치 불변

`docs/*.html` 대시보드 108쪽(5.8%)은 그대로. 주 결과(C·B)에는 계열 경고가 없고, 1차 산출물 `recoding_scores_AB.json` 에만 `family_warning` 이 남아 있다. 발표 여부·수치는 연구 책임자 판단이다.

### 6.6 lift 스크립트 부재

어휘 탐색(vocab-search.analysis.md §2.4)의 동시출현 lift 로직은 저장소에 남지 않았다. 채택 21종의 분포 영향(129 / 90쪽)만 `regrade.py`의 변형으로 재현.

### 6.7 B 원자료 결함 1건

id 385의 `latency_ms` = −1,159(벽시계 NTP 보정). 라벨과 무관하고 코드는 단조 시계로 고쳤다(R15l10). 원자료는 손대지 않음.

## 7. 교훈 (재사용 지식)

1. **같은 모델의 κ 0.914 는 코더 신뢰도가 아니었다** — 계열을 바꾸자 0.685 로 내려왔다. 1차 일치는 공통 편향을 보여준 것이지 정확도가 아니다. 계열 다양성이 필수.

2. **`claude -p` 의 MCP 도구 정의 누출(4.8만~11.8만 토큰)** — `--strict-mcp-config` + `--setting-sources ""` + `--tools ""` 강제, 저장소 밖 cwd 필수. 원칙 1(규칙 비노출)을 지키려면 기술적 강제가 필요하다.

3. **합집합 표본이 어휘 채택 순환을 끊었다** — 표본을 먼저 뽑으면 어휘 탐색 후 또 재코딩해야 하지만, 두 어휘의 합집합으로 뽑으면 같은 라벨로 어느 변형이든 채점할 수 있다. 채택이 라벨에 의존하지 않는다.

4. **전수 3층 + 재현율층 정확 초기하** — 표집오차 0인 전수에 단측 상한만 내는 초기하가 조합. 적중 0건이어도 "누락 0.8% 이하"를 말할 수 있다.

5. **산출물 삼각 검증 (R15q)** — 커밋된 `recoding_scores.json` ↔ `coding_key.json` ↔ `coding_C/B.json` 을 지문·항목 수·모델·전수 등급3 수로 대조. 라벨을 다시 만들고 채점을 건너뛰면 여기서 걸린다.
