- **절 경계**: `제3장 연구 결과` 본문 이후의 첫 일치(목차 제목 건너뜀), 1절 "1. 반도체고등학교…" ~ "2. NCS…", 2절 ~ "3. NCS 반도체 교과서의 사고…", 3절 ~ "4. 학생 대상…"

### 숫자 감사 (FR-09)

- 정규식 `\d(?:[\d,]*\d)?(?:\.\d+)?%?` 로 토큰 추출
- 정본값(포맷: 콤마·소수 1자리 % 문자열) + 파생 비율·쪽 번호와 대조
- 허용 목록(`ALLOWED_TOKENS`): 등급·분야 번호 0~4, 합계 100.0%, 60% 기준뿐 — 키워드 수 30 은 `value_index` 의 `keywords(count)`, 사고 연도는 `cases.gist` 에서 온다; 날짜·표/그림 번호·목차 번호는 감사 전에 걷어낸다(`STRIP_BEFORE_AUDIT`)
- 감사 범위: 1~3절의 모든 문단과 그 안에 중첩된 문단(표 셀·필드·메모 subList) — ship 리뷰 F5
- 미일치 토큰이 있으면 exit 1 → HWPX 쓰기 전 중단

- 1~3절 밖 최상위 문단의 `ET.tostring` 비교(구조·값 동일; ET 직렬화라 빈 태그 표기 `<x/>`→`<x />` 만 바뀔 수 있다) — 다르면 RuntimeError(쓰기 전)

## 재현 절차

### 환경 요구

- Python 3.9+ (3.9·3.13 에서 테스트)
- ImageMagick(`magick` 명령, `AppleGothic.ttf` 폰트 또는 사용 가능 폰트)
- 입력 파일: `docs/03-analysis/data/semantic_summary.json`·`accident_case_pages.json` (정본)

### 정본 실행 (추적 파일 생성)

```bash
python3 hwpx_results_refresh.py \
  --hwpx data/반도체 기초보고서_20260911.hwpx \
  --summary docs/03-analysis/data/semantic_summary.json \
  --cases docs/03-analysis/data/accident_case_pages.json \
  --out data/반도체 기초보고서_20260914_정본.hwpx \
  --diff-out docs/03-analysis/data/hwpx_results_refresh_20260914.json \
  --review-dir docs/03-analysis/hwpx-results-refresh \
  --text-review-dir data/hwpx-results-refresh
```

### 점검 실행 (산출물 검증, 추적 파일 쓰기 안 함)

```bash
python3 hwpx_results_refresh.py --no-render            # 대조 JSON 은 임시 디렉터리에 — --diff-out 은 docs/ 밖 경로만 허용
```

`--no-render` 는 그림을 그리지 않고 HWPX 도 쓰지 않는 점검 실행이다(magick 없는 CI 경로). 그림·HWPX 를 내려면 ImageMagick 이 필요하고, 같은 폰트·같은 입력이면 재실행 바이트가 같다(`-strip`).

### 테스트

```bash
python3 -m unittest test_hwpx_results_refresh          # 39 tests (magick 없으면 렌더 검사만 건너뜀)
```
