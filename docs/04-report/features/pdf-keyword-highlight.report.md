# PDF 형광펜 표시 완료 보고

> **Feature**: pdf-keyword-highlight
> **Completed**: 2026-09-26
> **Match Rate**: 100% (설계 §1~§12 전 항목 구현·검증, 정본 합계 12,724건 전수 대조)

## Executive Summary

| 구분 | 내용 |
|---|---|
| **Problem** | 정본 재검산(`semantic_keyword_recount_20260917.xlsx`)의 출현 12,724건이 표·숫자로만 존재해, 원본 PDF 문맥에서 실제로 어디에 있는지 눈으로 확인할 방법이 없었다. |
| **Solution** | 원본 PDF 95권을 사본으로 복사해 각 출현을 등급색 형광펜 주석으로 표시하는 도구(`highlight_pdf_occurrences.py`)를 만들었다. NCS 는 PDF 텍스트 층, 스캔본인 교과서는 Apple Vision OCR 로 글자 좌표를 얻고, 텍스트 층에 없는 표·그림·스크린샷 속 글자는 이웃 쪽·먼 쪽까지 OCR 로 재탐색한다. |
| **Function/UX Effect** | 연구 책임자가 PDF 뷰어에서 형광펜과 팝업(키워드·등급·정본 쪽·배치 사유)만으로 각 출현의 근거를 바로 확인할 수 있다. 원본은 건드리지 않고 사본에만 주석을 얹는다. |
| **Core Value** | 정본 데이터(등급·출현 수)를 왜곡하지 않으면서 시각적으로 검증 가능하게 만들었다 — 자리가 부족하면 옮기지 않고 겹쳐 표시하며, 근거가 약한 재배치는 하지 않는다(정본 쪽 밖 문맥 없는 OCR 배치를 두지 않은 것이 그 예). |

## 완료 내용

- 정본 xlsx 의 `NCS_매칭상세`·`교과서_매칭상세` 12,724행을 읽어, 정본과 같은 규칙 엔진(`semantic_keyword_recount.build_default_rules`)으로 줄 안 매칭 위치를 재현했다.
- 쪽의 글자를 추출 순서대로 정규화해 문자열 ↔ 좌표 대응을 만들고(`CharStream`), 마크다운 앞뒤 문맥 창(10→6→3→0자)으로 PDF 쪽 위의 자리를 찾았다.
- 배치 근거가 강한 순서로 10단계 정책을 적용했다(`resolve_row`, 설계 §9): 정본 쪽 → 이웃 쪽(문맥 6자+) → 정본 쪽 겹침 → 이웃 쪽(문맥 불문) → 정본 쪽 OCR(6자+) → 이웃 쪽 OCR(6자+) → 먼 쪽 텍스트(8자+) → 먼 쪽 OCR(8자+) → 정본 쪽 OCR(표현만) → 이웃 쪽 겹침.
- **연구 책임자 결정 ③(2026-09-26, "그림 속 글자 포함")**: 변환기가 그림·스크린샷을 OCR 해 본문처럼 넣은 문장(≈140건, 1.2%)도 출현으로 센다. 정본 수치(11,517·1,207)는 이미 그 출현을 포함해 바뀌지 않았고, 형광펜 도구만 이웃 쪽·먼 쪽 OCR 단계를 추가해 대응했다.
- OCR 스트림이 텍스트 층 글자도 함께 읽어 같은 자리를 "새 발견"으로 오판하지 않도록 겹침 가드(`_ocr_hit_is_new`)를 넣었다 — 결정 전후로 텍스트 층 기반 네 열(자기 자리·중복·±1쪽·먼 쪽)의 수치가 그대로 유지된 것이 그 증거다.
- 정본 쪽이 아닌 쪽에 문맥 없이 OCR 로 배치하는 단계는 의도적으로 두지 않았다(진단에서 앞부속 예시 그림의 오배치 사례를 확인했기 때문).

- 먼 쪽 OCR 37건 중 29건은 개발·장비 분야 교재의 앞부속 "NCS 학습모듈의 내용 체계" 표다. 이미지 전용 쪽이라 텍스트 층이 비었고, 줄→쪽 대응이 정본 10쪽·실제 7쪽으로 3쪽 어긋나 있었다 — 렌더로 "안전·유의 사항" 칸에 형광펜이 정확히 놓인 것을 확인했다.
- 남은 미발견 51건: 앞부속 예시 그림 "위생" 14건(먼 쪽 문맥 기준 8자 미만이라 놓지 않음), 『CMP 슬러리 재료 제조』 9건, 『반도체 장비 안전관리』 6건, OCR 오인식(`Fire`·`Radiation`·`X-선`), 영문 표현(`electric shock`). 먼 쪽 문맥 기준을 낮추지 않는 한 도구로는 더 못 찾는다 — 연구 판단이 필요하면 `unresolved.csv` 참조.
- 95권 전부 출력 PDF 의 형광펜 수 = 배치 행 수 + 원본 기존 주석(`preexisting_annots`)으로 대조해 일치를 확인했다.
