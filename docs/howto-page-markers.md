# How to 마크다운에 PDF 쪽 번호 붙이기

검색 결과의 **위치** 열을 줄 번호(`L12`)에서 실제 PDF 쪽수로 바꿉니다. `insert_page_markers.py` 가 `_meta.json` 의 목차를 읽어 마크다운에 `<!-- page: N -->` 주석을 심습니다.

한 번 심어 두면 검색 앱이 목차 매칭을 아예 건너뜁니다. 앱의 `buildPageMapping` 은 마커를 최우선 전략으로 쓰고, 마커가 하나라도 있으면 목차 기반 추정(2순위)을 돌리지 않습니다. 추정이 아니라 확정값이 됩니다.

## 준비

- **Python 3.** pip 패키지는 필요 없습니다. `page_utils.py` 만 씁니다(저장소에 있음).
- **`.md` 와 짝이 되는 `_meta.json`.** 같은 폴더에 있어야 합니다.

`_meta.json` 은 이 모양이어야 합니다:

```json
{
  "table_of_contents": [
    { "title": "적용범위",        "page_id": 1 },
    { "title": "안전 유의 사항",  "page_id": 4 },
    { "title": "사고 사례",       "page_id": 9 }
  ]
}
```

**`page_id` 는 0-based 입니다.** 스크립트가 1을 더해 씁니다 — 위 `page_id: 1` 은 `<!-- page: 2 -->` 로 들어갑니다. 변환기가 이미 1-based로 뱉는다면 쪽수가 하나씩 밀립니다.

짝 찾기는 파일 이름으로 합니다. `sample.md` → `sample_meta.json`. 변환기가 붙이는 `20260121_174526_` 같은 날짜 접두사는 무시하고 매칭합니다.

## 1. 먼저 dry-run

**항상 `--dry-run` 부터 돌리세요.** 스크립트는 원본을 제자리에서 덮어씁니다.

```bash
python3 insert_page_markers.py --dry-run /path/to/문서폴더
```

```
=== DRY RUN 모드 (변경 없음) ===

  INSERT 예정 (3페이지): sample.md

=== DRY RUN 결과 ===
  전체 파일: 1
  마커 삽입예정: 1
  이미 마커 있음: 0
  meta.json 없음: 0
  매핑 실패: 0
```

**디렉터리 인자를 반드시 주세요.** 생략하면 코드에 박힌 작성자 로컬 경로(`DEFAULT_NCS_DIRS`)로 갑니다. 그 경로가 없으면 `경고: 디렉토리 없음` 만 찍고 아무 일도 안 합니다.

하위 폴더까지 재귀적으로 훑습니다.

## 2. 백업하고 삽입

```bash
python3 insert_page_markers.py --backup /path/to/문서폴더
```

```
  DONE (3페이지): sample.md

=== 결과 ===
  전체 파일: 1
  마커 삽입완료: 1
  이미 마커 있음: 0
  meta.json 없음: 0
  매핑 실패: 0
```

`--backup` 은 원본을 `<파일명>.md.bak` 으로 남깁니다. 버전 관리 밖에 있는 문서라면 붙이세요.

결과는 이렇게 됩니다. 마커는 **쪽이 바뀌는 지점에만** 들어갑니다:

```markdown
<!-- page: 2 -->
# 적용범위

이 문서는 반도체 공정 안전을 다룬다.

<!-- page: 5 -->
## 안전 유의 사항

보호구를 착용하고 작업한다.
```

## 3. 확인

```bash
# 마커가 몇 개 들어갔나
grep -c 'page:' /path/to/문서폴더/sample.md

# 어느 쪽들이 잡혔나
grep -o '<!-- page: [0-9]* -->' /path/to/문서폴더/sample.md
```

그리고 [검색 앱](tutorial-first-search.md)에서 그 폴더를 다시 검색해 보세요. **위치** 열이 `L12` 대신 쪽수로 바뀌어 있어야 합니다.

## 건너뛰는 파일

스크립트가 조용히 넘기는 경우가 넷 있습니다. dry-run 요약의 각 줄이 그 개수입니다.

| 요약 줄 | 뜻 | 대처 |
|---|---|---|
| `이미 마커 있음` | `<!-- page: N -->` 이 이미 있음 | 다시 심으려면 아래 참조 |
| `meta.json 없음` | 같은 폴더에 짝이 되는 `_meta.json` 이 없음 | 변환기가 메타를 냈는지 확인 |
| `매핑 실패` | 목차 제목이 문서의 제목 줄과 하나도 안 맞음 | 제목 표기가 다르거나 목차가 비어 있음 |
| (요약에 안 나옴) | 경로에 `report` 가 들어간 파일 | 의도된 제외. 분석 보고서를 건드리지 않으려는 것 |

`report` 제외는 대소문자를 가리지 않고 **경로 전체**를 봅니다. `annual_report.md` 도, `reports/` 폴더 안의 모든 파일도 빠집니다.

## 다시 심어야 할 때

`--force` 플래그가 있지만 **아무 일도 하지 않습니다.** 선언만 되어 있고 실행 경로에서 쓰이지 않습니다. 마커가 이미 있는 파일에 붙여 돌려도 결과는 이렇습니다:

```
  전체 파일: 1
  마커 삽입완료: 0
  이미 마커 있음: 1
```

마커가 중복으로 쌓이지는 않으니 안전하지만, 다시 심고 싶다면 직접 지워야 합니다:

```bash
# 마커 줄만 제거 (되돌릴 수 없습니다 — 먼저 백업하세요)
sed -i.bak '/^<!-- page: [0-9]* -->$/d' /path/to/문서폴더/sample.md
```

`--backup` 으로 받아둔 `.md.bak` 이 있다면 그걸 되돌리는 쪽이 안전합니다.

## 왜 마커를 쓰는가

앱과 `page_utils.build_page_map()` 은 쪽수를 두 전략으로 구합니다.

1. **`<!-- page: N -->` 마커** — 마커를 만나면 그 쪽 번호를 아래 줄들에 그대로 물려줍니다. 확정값입니다.
2. **목차 기반 3단계 매칭** — 제목 줄을 목차 항목에 맞춰 보고, 중복 제목은 동적 계획법으로 최적 배정을 찾고, 매칭된 제목의 쪽수를 아래로 전파합니다. 추정입니다.

1번이 하나라도 있으면 2번은 아예 돌지 않습니다. 마커를 심는다는 건 추정 단계를 영구히 우회한다는 뜻입니다.

모든 문서에 마커가 들어가면 앱의 2번 경로(약 200줄)는 죽은 코드가 됩니다. `TODOS.md` 의 미해결 항목입니다.

## 막혔을 때

**`경고: 디렉토리 없음` 만 찍고 끝난다**
디렉터리 인자를 안 줬습니다. `DEFAULT_NCS_DIRS` 는 작성자 머신의 절대 경로라 다른 환경에서는 존재하지 않습니다.

**전부 `매핑 실패` 로 빠진다**
목차 제목과 문서의 제목 줄이 안 맞습니다. 제목 판정은 `#` 마크다운, `○●◆◇■□▶▷` 표식, `(가)` · `1.` 번호 패턴을 제목으로 봅니다. 문서의 제목이 이 중 어디에도 안 걸리면 매칭할 대상 자체가 없습니다.

**쪽수가 하나씩 밀린다**
`page_id` 를 1-based로 넣었습니다. 스크립트는 0-based를 가정하고 1을 더합니다.

**마커가 있는데도 검색 결과가 줄 번호로 나온다**
앱이 검색한 폴더와 마커를 심은 폴더가 다른지 확인하세요. 앱은 브라우저에서 폴더를 다시 고를 때 파일을 새로 읽습니다.
